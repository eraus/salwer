# salwer---SaLAI Lab's WER Calculation Toolkit

## Introduction

salwer is a comprehensive toolkit for calculating Word Error Rate (WER) at both the segment and word levels, developed by ERAU's SaLAI Lab. The need comes from granular WER analysis for ASR tools for Air Traffic Control (ATC) applications.

The motivation for using segment- and word-level WER analysis, along with the detailed algorithms, is discussed in [@SALWER-Liu2026].

## Functional Classification and Semantic Segmentation of ATC Cues

### Format of Transcripts

salwer focuses on evaluating transcriptions of long audio files, such as ATC communication recordings. The reference and inference transcripts are stored in VTT or SRT format---common subtitle formats that support time-aligned cues.

In our examples, we use ATC communication transcriptions, where each cue represents a single transmission from either a controller or a pilot. These transcripts are organized into separate folders:

-   `reference/`: Contains the ground truth transcripts.
-   `inference/`: Contains the transcripts generated by the ASR system.

Each cue in the VTT/SRT file is aligned by timestamps, allowing salwer to compare the reference and inference transcripts cue-by-cue.

salwer supports semantic segmentation of ATC transmissions in the reference files using a two-step process:


### Functional Classification

Each transmission is classified into a functional category based on its role in the communication.

-   **ATC-IA:** ATC transmissions containing instructions for immediate avionics (IA) operations (e.g., heading or altitude changes).
-   **PLT-RA:** Pilot (PLT) readbacks corresponding to ATC-IA messages (RA stands for readback for avionics operation).
-   **ATC-OT:** Other (OT) ATC transmissions, including future-phase instructions (e.g., speed constraints to a waypoint), acknowledgments, and routine exchanges. These do not require immediate information/instruction extraction as pilots have sufficient time for such actions.
-   **PLT-OT:** Other pilot transmissions, including readbacks for non-avionics instructions, requests, and routine exchanges.


### Semantic Segmentation

A transmission can contain one or more of the following semantic segments, which have varying relevance to action/value pair extraction for voice-assisted avionics:

-   **A. Callsign:** Aircraft identifier.
-   **B. Action:** A verb phrase indicating the instructed or intended avionics operation (e.g., "climb," "descend," "turn") in ATC-IA or PLT-RA.
-   **C. Value:** Numeric parameters of an action, including units, in ATC-IA or PLT-RA. Actions and values are further classified by type: (1) altimeter, (2) altitude, (3) frequency, (4) heading, (5) speed, (6) squawk.
-   **D. Acknowledge:** Short confirmations such as "roger," "wilco," "affirm," "will do," and "radar contact."
-   **E. Info:** Expressions providing information only (e.g., "going from 4 to 5" where pilot reports that they are groing from 4 thousand feet to 5 thousand feet, which is not part of a required readback). If part of a readback, it would be classified as action and value.
-   **F. Condition:** Conditional phrases indicating when an action should occur (e.g., "after passing," "when able") in ATC-IA or PLT-RA.
-   **G. Facility:** Identifiers for facilities without unique names (except city names), including ATC positions, runways, ILS identifiers, and DME references.
-   **H. Navaid:** Named geographic points (e.g., "JFK VOR," "ALBANY").
-   **I. Greeting/Farewell:** Salutations such as "good morning," "good day," "hello," and "goodbye."
-   **J. Other:** Everything that cannot be classified into the above segments.


### Exemplary transcript files

To help users get started quickly, we provide a set of exemplary transcript files hosted in the `salwer/examples/files_for_wer` folder. Reference transcript files---derived from the LDC ATC0 dataset [@AirTrafficControl-Godfrey1994a]---are located in the `ref` folder and include classification and segmentation labels. Hypothesis (inference) transcript files are located in the `b12_aug2_l12` folder (Batch 1 and 2 files for fine-tuning with Augmentation Approach 2, evaluated on Level 1 and 2 cues). See [@ATC-ASR-VAA-LiuPandey2026] for further details.


## Running Examples

Once installed, the tool can run anywhere on your computer. It is often convenient to run it in the directory where your transcript data resides.

### Average WER Calculation

The `salwer calculate-average-wer` (or `salwer caw`) command computes **three types of average WER**:

-   **All words**: Standard average WER over all words.
-   **First words**: WER of only the first word in each transmission.
-   **Second+ words**: WER of all words except the first.

The latter two modes are motivated by our observation that first-word WER often differs substantially from other words. These modes are implemented using segment-level Levenshtein edit distance (LD) calculation.

**Command options**:

-   `--level: int=3`: Audio quality level (1, 2, or 3).
-   `--words: str`: Specifies which words to include in the average WER calculation:
    -   `all` (default): Computes the standard average WER over all words.
    -   `first`: Computes WER for only the first word of each transmission. This option is motivated by our observation that first-word WER tends to be higher than other words. Implementation uses segment-level LD calculation.
    -   `second+`: Computes WER for all words except the first in each transmission. Also implemented using segment-level LD calculation.
-   `--approach: str`: Selects the algorithm version when `--words` is set to `first` or `second+`:
    - `normal` (default): Uses the `levenshtein_seg` function.
    - `fast`: Uses the `levenshtein_seg_fast` function.

**Application example**:

We compute three different average WERs using files in the `ref` (reference) and `b12_aug2_l12` (hypothesis) folders, as described previously. Details of the fine-tuned ASR models are provided in [@ATC-ASR-VAA-LiuPandey2026]. The results are shown in Table \ref{tbl:average-wer}. The commands used are:

```sh
# Average WER over all words
salwer caw ref b12_aug2_l12 --level 2

# Average WER for the first word in each cue only
salwer caw ref b12_aug2_l12 --level 2 --words first

# Average WER for all words except the first in each cue
salwer caw ref b12_aug2_l12 --level 2 --words second+
```


### Segment-Level WER Calculation

While the `salwer caw` command computes WER on *fixed segments* (first word vs. remainder), the `salwer calculate-seg-wer` (or `salwer csw`) command computes WER on **user-defined semantic segments**.

**Command options**:

-   `--level: int=3`: Audio quality level (1, 2, or 3).
-   `--class: str=1`: Selects the functional class for WER calculation.
-   `--segment: str=A`: Selects a semantic segment for WER calculation.
-   `--approach: str=normal`: Calculation approach for segment-based LD (`normal` or `fast`).
-   `--no-tight: bool=False`. Excludes prefix drift before each segment; by default prefix drift is included (via `False`); to exclude, use `--tight` in command line.

**Note**: Classification and segmentation are application-specific. Example labeled transcripts are available in `salwer/examples/files_for_wer/ref`.

For voice-controlled avionics applications, we are primarily interested in the performance of segments that carry action and value information.

**Application example**:

We compute segment-level WERs for two classes and three semantic segments using files in the `ref` and `b12_aug2_l12` folders. More detailed analysis based on an early version of the tool is provided in [@ATC-ASR-VAA-LiuPandey2026]. The commands used are:

```sh
# Class 1, Segment A (default) for Levels 1 and 2
salwer csw ref b12_aug2_l12 --level 2

# Class 1, Segment B
salwer csw ref b12_aug2_l12 --level 2 --segment B

# Class 2, Segment A
salwer csw ref b12_aug2_l12 --level 2 --class 2

# Class 2, Segment B
salwer csw ref b12_aug2_l12 --level 2 --class 2 --segment B
```


### Word-Level WER Calculation

Word-level WER calculation provides per-word error rates for selected classes and segments. This enables detailed analysis---such as WER vs. word frequency or sample size---that can guide ASR fine-tuning strategies. For details, see [@WL-WER4ATC-PandeyLiu2026].

The command is `salwer calculate-word-wer` (or `salwer cww`).

**Command options**:

-   `--level: int=3`: Audio quality level (1, 2, or 3).
-   `--class: str=all`: Selects the functional class for WER calculation. Individual classes can be used, or `all` (default) to aggregate across classes.
-   `--segment: str=all`: Selects a semantic segment to filter by. Use `all` (default) to include all segments.
-   `--err-limit: float=3.0`: Sets the maximum generalized LD (GLD) per word (e.g., `3.0` caps WER at 300% per word). This limits the impact of extreme hallucinations on reported WER.

**Application example**:

We compute word-level WERs for selected digit words in Class 1 across two semantic segments: Segment A (callsigns) and Segment C (values). The commands used are:

```sh
# Class 1, Segment A
salwer cww ref b12_aug2_l12 --level 2 --class 1 --segment A

# Class 1, Segment C
salwer cww ref b12_aug2_l12 --level 2 --class 1 --segment C
```

**Note**: After each run, results are saved as a timestamped CSV file in `files_for_wer/log`. The file is also copied to `word-dict.csv` to facilitate script-based processing.


### Additional Functionalities

The tool provides several auxiliary commands:

-   `salwer plt`: Print Levenshtein edit distance tables.
-   `salwer classify-segment`: Perform ATC cue classification and segmentation using LLMs.
-   `salwer inspect`: Inspect segmentation results.
-   `salwer obtain-word-count`: Obtain word count for training or test datasets.

For a full list of commands, run `salwer --help`.
